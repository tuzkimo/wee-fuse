# 按色号批量换色设计

> 2026-10-11。人类伙伴与助手头脑风暴的产物。**本文是真源**：实现计划、构建记录里关于本功能的
> 语义一律引本文，不要各写一份。

## 1. 意图与 why

人类伙伴的原话场景：**两个色块的交界处存在大量离散的过渡色点**——图片缩放与逐格取色会在交界处
留下一批「谁都不像」的色号，每个用量都很小（几颗到几十颗）。想把它们归到旁边那块正经颜色上。

现有工具一个都干不了这件事：

- 画笔：一格一格点，几十个离散点就是几十次点击，不可行（这是人类伙伴的原话理由）。
- 橡皮 / 去背景：只能抠掉，不能「归到旁边的颜色」；而去背景吃的是**连通**区域，交界过渡点恰恰
  不连通。
- 框选：过渡点是沿边界散开的曲线，矩形框不住。

而编辑页**没有任何入口**能表达「把这个色号的所有格子改掉」：已用色列表的行只做一件事——
设当前画笔色。

## 2. 目标

1. 编辑页的**已用色列表的行变成多选开关**：点行选中该色号、再点取消；选中的色号在**画布上高亮**
   它们占的全部格子（过渡点本来是散的，看不见选中了什么就没法确认没误伤）。
2. 有选中时出现一条**操作条**：`[换成…]` 打开选择器选目标色 → 整批一次改完、**一步撤销**。
   目标可以是**橡皮（空格）**（清过渡色时批量擦掉往往比换色更有用）。
3. 选择器顶部列出**当前使用的颜色**，点一下就把当前画笔换成它——补上第 1 条拿走的那条快捷路径。

## 3. 非目标

- **不做**「按色号自动 / 一键整图删除同类色」（无预览、人没看过就要落地的改动）。理由见 §4。
- **不做**按颜色相近（ΔE / 阈值）自动归并过渡色，也不做阈值滑条：过渡色要不要归、归到哪个色
  是人的判断，本批只提供「人点选、机器执行」。
- **不做**「选择器里选色即换色」的隐式语义（§5.4）。
- **不做**框选内换色、不做选区的保存 / 撤销 / 命名、不做跨会话保留选择。
- 不动 `core` 的 `Pattern` / `EMPTY` 语义、导出、施工图、落盘格式与任何参数。

## 4. 先例与推翻（必读）

去背景规格（`2026-10-11-background-removal-design.md`）**§3 非目标**写着「不做『按色号全图删除
同类色』（渐变背景会漏，且会误伤主体同色区域）」，**§10 延后项**又列了同一条。本批**部分兑现**
了那条延后项，但**不是把它作废**——两件事的失败模式不同：

- 当时拒绝的是**以背景识别为目的、无预览的一键整图删除**：用户按下按钮之前不知道哪些格子会没，
  主体里与背景同色的区域会被不可预期地吃掉。
- 本批做的是**人工点选 + 画布预览 + 一步撤销**：会被改的格子在按下按钮之前**已经画在屏幕上**，
  人看过才执行；撤销一步全还原。

所以「误伤主体同色区域」这条风险由**预览 + 撤销**接住了，而「渐变会漏」在按色号换色里根本不是
问题（换的是全图同色号，不存在连通与否）。这是**人类伙伴 2026-10-11 在头脑风暴中明确要的功能**
（裁定记录即本节）。

## 5. 交互与状态（已定）

### 5.1 已用色行 = 多选开关

- 行点击 = 选中该色号 / 再点取消（**不再**设当前画笔色）。
- 行上同时保留既有的 `data-current` 高亮（=「当前画笔色是这一行」这条信息仍然有用），
  选中态是**另一个**标记：选中行加一圈实线边框，`data-selected="1"`。
- 行序、色号、颗数一律不变（仍取 `usages` 自己的顺序）。

### 5.2 操作条

- 只在「有效选中 ≥ 1 个色号」时渲染：`已选 2 个色号 · 共 37 颗` + `[换成…]` + `[取消选择]`。
- **位置：选择器之后、色号列表之前。** 不能插到当前色槽与选择器之间——C8 修复 ③b 钉下的不变式是
  「选择器是当前色槽的**下一个兄弟元素**」，插在中间会让那条（真机截图换来的）守卫转红。
- `[换成…]` 打开选择器，并告诉它这次是「选目标色」。
- 颗数 = 有效选中的那些行自己的 `count` 之和（见 §7 第 1 条）。

### 5.3 选择器的两种用途

- 新增入参区分用途：**画笔色**（默认，点一下即设当前色并收起）与**换色目标**（由 `[换成…]` 进入，
  点一下即整批换色并收起）。
- 新增顶部「**已用色**」组：按 `usages` 顺序列出当前用到的色号，点一下 = 设当前画笔色（这条快捷
  路径就是第 1 条拿走的那条）。**这一组与色卡网格服从同一条规则：它们的用途 = 选择器当前的用途。**
  也就是说换色模式下它是**目标色**（不是画笔色）——把过渡色归到旁边**已经在用**的那个颜色是最常见的
  落点，若这一组在换色模式下仍改画笔，用户就得去 221 色网格里翻那个色。这是我的判断，不是人类伙伴
  逐字要求的。**这一组用独立的 `testid` 与属性**（`data-testid="picker-used"` +
  `data-used-code`），不带 `data-code` / `data-used`：那两个属性是色卡网格的钩子，同一色号出现在两处
  会让既有的「已用色标记」用例一次命中两个元素（`get` 抛错、`findAll` 数量翻倍）。
- 换色模式下**多一颗「橡皮（空格）」**（`data-testid="picker-eraser"`），点它 = 目标是 `EMPTY`。
  画笔模式下不渲染它——工具栏已经有一颗独立的橡皮按钮。
- **有选中时点当前色槽，进的仍是画笔模式**：色槽永远是「改画笔色」的入口，换色只能经 `[换成…]`
  （§5.4 的直接后果）。这时选中与操作条都保留，用户挑完画笔色回来还能接着换。

### 5.4 不做隐式语义（我的判断）

「有选中时，选择器里选色 = 换色目标；没选中时 = 画笔色」这种同一动作双含义的写法**不做**：
用户手上挂着选择、只想改画笔色时，一按就误改一整片。多一次点击（`[换成…]`）换「不会误伤」。

### 5.5 选中集合是动态集合

选中的是「**该色号的所有格子**」，不是一份固定下标清单：选择挂着时手动涂了一格该色号，它立刻跟
着高亮，也会被一起换掉。这是集合语义，不是 bug。

实现上的落点：页面持的是**色号集合**（不是预先算好的格子下标清单），画布在 `draw()` 里扫 `cells`
判定——于是「涂一格 → 立刻高亮」由既有的 `revision` 重绘通道天然覆盖，页面不需要在每次 `revision`
上重算一份下标。**谁预先算下标谁就欠一条重算依赖**，那正是「不报错、只是画面不动」的那类缺陷。

### 5.6 选中态放页面，不落 store

画布也要读它（高亮），所以它不能像框选高亮那样留在组件内。放 `EditorPage` 的一个 `ref`，面板与画布
各收 props、各发事件——与 `EditorPage` 既有的装配方式一致（四个编辑器组件都不 import store），
并且改动面最小。**选择是 UI 状态，不是图纸状态**：不进 `EditHistory`、不进落盘、不参与撤销。

### 5.7 清空选择的时机

- 换色提交之后（不论图纸是否真的变了，见 §7 第 3 条）。
- 点 `[取消选择]`。
- 页面载入另一份图纸 / 卸载（`activate` 与 `reset` 那条路）。

## 6. 实现面（逐文件的决定）

| 文件 | 改什么 |
|---|---|
| `src/core/pattern/edit.ts` | 新增纯函数 `indicesWithValues(cells, values)`：返回值落在 `values` 里的格子下标（升序、行优先）。判定「哪些格子要改」是 core 的职责（与 `patternBackgroundIndices` 同口径），store 只负责入账。 |
| `src/stores/editor.ts` | 新增动作 `recolor(sources, to)`：入口校验 → `indicesWithValues` → 既有的 `buildPaintCommand` → `history.commit` → `publishChange`。**不新写任何判定 / 入账逻辑。** |
| `src/components/editor/PalettePicker.vue` | 新入参（画笔色 / 换色目标）、顶部「已用色」组、换色模式下的「橡皮（空格）」。 |
| `src/components/editor/PalettePanel.vue` | 行改多选开关；操作条；`[换成…]` 进入换色模式；把有效选中连同事件一起发出去。 |
| `src/components/editor/PatternCanvas.vue` | 新 prop（选中色号）→ 叠加层画一层高亮；`watch` 要把它算进去。 |
| `src/views/EditorPage.vue` | 持有选中集合的 `ref`、接线、换色后与换图时清空。 |

两个口径细节：

- **选中集合每次都是新数组，绝不原地改**（与 `lastDirty` 同口径）。画布的重绘判据是浅比较，
  原地 `push` 会让高亮不刷新——这是「不报错、只是不动」的那类缺陷。
- **换色只能有一个目标色**：多个源色号一起归到一个目标（人类伙伴选的就是这条，不是「每个源色各配
  一个目标」）。

## 7. 边界与失败模式

1. **选中的色号在选中期间被改光**（手动擦干净）：那一行从 `usages` 里消失了，但集合里还留着它。
   于是操作条**按「当前仍在用的那些」计数**——否则 UI 会撒谎（显示「已选 2 个色号」而实际只会改
   1 个）。全都消失时操作条不渲染，也就点不到换色。
2. **目标色与源色相同**（只选了一个色号、又换了它自己）：`buildPaintCommand` 返回 `null`
   ⇒ 不入栈、不置脏、不消耗撤销额度。这是既有契约（点一个已经是当前色的格子同理）。
3. **上一条的后果**：那次换色是空操作，但选择仍被清空（§5.7）。接受——图纸确实没变，用户看得见
   画面没动、重选一次即可；为它加一条「动作返回值」的 API 不划算。
4. **选中的色号数是 0**：操作条不渲染，换色入口不存在；`recolor` 拿到空数组时
   `indicesWithValues` 返回空、`buildPaintCommand` 返回 `null`（不置脏）。
5. **源色里混着色卡外的值**：store 的入口校验响亮失败（与 `setCurrentColor` 同一值域口径）；
   页面只把有效选中的部分交出去（§5.2）。
6. **目标是 `EMPTY`**：合法，等价于批量擦除。
7. **撤销 / 重做**：与选择无关。换色一步撤销把整批还原；撤销时选择已经清空，不会留下高亮残影。
8. **切换工程 / 卸载 / 重新载入**：选择清空（§5.7）。
9. **`EMPTY` 出现在源色里**：面板永远交不出这种集合（`usages` 不含空格），core 不额外拦它。

## 8. 测试要求

core：

- `indicesWithValues`：单色号命中全部格；多色号取并集；空数组 → 空；非整数 / 负数 / 越界值 → 抛错；
  「色卡里存在但图纸里没有的色号」→ 空（不是抛错）。
- 换色命令：`buildPaintCommand` 已有的「已经是目标值不入账」契约在新路径上同样成立（空命令 ⇒ 无撤销记录）。

store：

- 一次 `recolor` = 一条撤销记录、一步 undo 全部还原；
- 空源 / 目标等于源 ⇒ 不置脏、不动 `revision`、不消耗撤销额度；
- 源越界 ⇒ 抛错；`to` 越界 ⇒ 抛错（`EMPTY` 合法）；
- 不置脏的动作清单（既有用例）不受影响。

组件：

- 面板：点行 toggle 选中、**不**改当前色、**不**展开选择器（三件事一起断言）；选中行带 `data-selected`；
  操作条按有效选中计数、数目为 0 时不渲染；`[换成…]` 打开选择器且处于换色模式；
  换色模式点色（含橡皮）emit 出**有效源色集合 + 目标值**；换色模式点关闭不 emit 换色；
  `[取消选择]` emit 空集合。
- 选择器：顶部「已用色」组按 `usages` 顺序列出、点一下 emit 该色的**全色卡下标**；空 `usedIndices`
  时不渲染这一组；「已用色」组的元素**不带** `data-code` / `data-used`（既有网格钩子的唯一性）；
  橡皮项只在换色模式渲染、emit `EMPTY`。
- 画布：选中色号的格子在可见范围内被高亮填充、未选中的格子不被填充；**换一个选中集合要重绘**
  （浅比较那条的守卫）。
- 页面：接线端到端 —— 点行选中 → 点 `[换成…]` → 点目标色 ⇒ 图纸那批格子确实变了、选中被清空、
  用量表更新；载入另一份图纸后选择已清空。

**要改写的既有断言（人类伙伴已确认）**：`PalettePanel.test.ts` 里两条以「点行 = 换当前色」为前提的
用例（「点某一行 emit 的是全色卡下标」「点行只换当前色，不会顺手展开选择器」）——它们与新规格**直接
冲突**，按 `AGENTS.md` 的例外条款改写为「点行 = 切换选中」，判别核心（emit 的是全色卡下标而不是
`usages` 里的位置、点行不展开选择器）**一条不丢**。

## 9. 留给实现者的裁定

- 文案（操作条、橡皮项、选择器标题）、图标、颜色深浅：按现有 UI 风格自取。
- 高亮的具体取值：与框选同族（`rgba(37, 99, 235, …)`），透明度自取；真机上小格子要看得清。
- 「已用色」组在色卡网格之前还是之后、要不要显示颗数：它在顶部，顺序自取（颗数只有面板有，
  这一组**不**显示颗数）。
- 操作条的 DOM 细节与 `testid` 命名（本文给的名字是建议，实现时与既有命名风格对齐即可）。

## 10. 延后项（本文暂不做）

- ΔE / 阈值自动归并过渡色、容差滑条；
- 「按色号自动删除」这类无预览的一键整图改动；
- 框选 / 套索范围内换色；
- 选区的保存、命名、跨会话保留；
- 把选中集合移进 store（出现第二个消费者时再说）。
