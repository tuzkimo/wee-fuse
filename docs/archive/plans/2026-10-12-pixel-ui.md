# 像素风 UI 重设计实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> 本项目既有的执行约定（见 `docs/开发约定详解.md`「开发流程」）：写任务简报 → **子代理**实现 →
> 控制者自己复核每一条承重声明 → **全新子代理**做任务级审查 → 修复轮，每轮以一次定向复审收尾。

**Goal:** 把 5 个用户可见页面重做成「拼豆板」像素风（暖米色操作区 + 深色看图区 + 像素字体 + 图形按钮），并把编辑器工具集从 5 个按钮收到 3 个（画笔 / 填充 / 橡皮），手机竖屏与平板横屏各有一套排法。

**Architecture:** 三层，按依赖顺序做。**① 功能层**（任务 1–4）：先改工具集——删吸管、删框选、把「去背景」泛化成「填充」，这样后面的视觉工作只重写一次工具栏。**② 设计系统**（任务 5–7）：`src/style.css` 的 Tailwind v4 `@theme` token + 像素字体 + 两个原子组件（`PixelIcon` / `BeadButton`），全部像素感由纯 CSS（4px 描边 + 零模糊硬投影）与内联 SVG 表达，**不引入任何位图资产**。**③ 逐屏**（任务 8–18）：每屏独立一个任务，`data-testid` 一律不改名（封闭清单见 Global Constraints），按钮的可见文字换成图标时中文词进 `aria-label`。

**Tech Stack:** Vue 3 + TypeScript（严格模式）+ Pinia + Tailwind CSS v4（CSS-first `@theme`）+ Vitest。**零新增依赖**；唯一新增二进制是字体文件。

**Spec:** `docs/superpowers/specs/2026-10-12-pixel-ui-design.md`（下文所有 `§N` 都指这份）

## Global Constraints

- **只改本计划列出的文件**；不改依赖、不改 `package.json` / lockfile、不动无关代码。
- **`data-testid` 封闭清单**（§11.1）：允许删 / 改名 / 挪位置的**只有** `tool-select`、`tool-pick`、
  `tool-background`→`tool-fill`、`toolbar-row-{tools,history,display,view,output}`、`result-stats`、
  `result-size` 这 10 个。其余 138 个**一个都不许改名、不许删**；挪位置（进 `gear`、从卡片搬到主体按钮）
  是允许的，用例改成「多点一下」但 testid 不变。`§11.1` 的「容易被误删」清单逐个点名了它们。
- **允许改写的既有断言，就是 §11.2 那几条 + 一处 §11.2 漏列的**：`components/editor/__tests__/PatternCanvas.test.ts`
  里以 `tool: "select"` / `"pick"` / `"background"` 为前提的用例（改名或整例删除）。
  **其余既有断言一律不许放宽、删除或改弱。** 发现别的冲突先停下来问。
- **`src/core/**` 是纯计算层**：不得 import `vue` / `pinia` / `@tauri-apps/*`、不得引用 DOM 全局
  （闸门 `src/__tests__/coreBoundary.test.ts` 必须保持绿）。本计划在 core 里**只有删代码**
  （任务 3 删 `buildRectPaintCommand`），不新增。
- **像素风的三条禁令**（§4 反目标，最容易被违反）：
  1. **不许引入位图资产**（9-slice PNG、雪碧图、锯齿边框贴图）。像素感只由 CSS + 内联 SVG 表达。
  2. **不许 `transform: scale()`**（会破坏像素字体的整数倍栅格，字会糊）。
  3. **不许 `font-weight`**（`font-bold` / `font-semibold` / `font-medium` 全删）。像素字体没有真粗体，
     浏览器合成的假粗体会把中文笔画糊成一团。
- **字号只有三档 `12` / `24` / `36`（px），必须能被 12 整除**；**图标尺寸只有 `12` / `24` / `36` / `48`**
  （12 的整数倍）。两者共享同一个 12 栅格，写错不是编译错误，是静默的糊。
- **不许用 Tailwind 默认调色板**（`slate-*` / `gray-*` / `amber-*` / `red-*` / `blue-*` / `green-*` /
  `white` / `black`），一律走 `bead-*` token。
- **描边只有 `4px`（标准）与 `3px`（小元素）两档**；**硬投影零模糊半径**（`shadow-pop-*`），
  Tailwind 的 `shadow-sm/md/lg` 一律不用。
- **每个图标按钮必须带 `aria-label`，值是原来那个中文词**（「画笔」「撤销」「保存」…）。漏一个就是
  无障碍缺陷 + 该按钮按名字找的用例失效。
- **最小触控目标 `56×56px`**，主工具 `64×64px`，圆图标按钮 `50~56px`。手机端**不许靠缩小按钮**来放下东西。
- **深色底 `bead-board` 只允许出现在四处**：`PatternCanvas` / `ResultPanel` / `SheetViewer` /
  `SetupPage` 的中栏（§10.6）。
- TypeScript 严格模式，禁止 `any`；公开 API 的入口校验写在任何写操作之前，非法输入**响亮失败**。
- 提交信息：Conventional Commits + 中文描述。
- 每个任务结束跑 `npm run test`；**每个任务结束还要跑 `npm run build`**（本计划大量改模板，`vue-tsc`
  是唯一能抓到类型与 props 漂移的闸门，`vitest` 不做类型检查）。
- 测试文件放对应目录的 `__tests__/` 下，沿用该文件既有的夹具风格。

## Review Focus

规格没写、但真实使用中最可能咬人的五类输入。每条都在拥有那段代码的任务里有对应的测试或检查步骤：

1. **手机底部安全区**：孩子用平板/手机时底部有系统手势条，固定底栏（`SetupPage` 的主按钮、`EditorPage`
   的工具条）会被盖住，按钮点不到。期望 `env(safe-area-inset-bottom)` 进入固定底栏的内边距
   （→ 任务 11、12）。
2. **长作品名**：`LibraryPage` 卡片改成 2 列后比现在窄，名字在 24px 字体下若撑开网格会导致整页横向滚动。
   期望沿用既有 `.project-name` 的 `overflow-wrap: anywhere` 口径且不撑破 2 列轨道（→ 任务 8）。
3. **深色底上的色号可读性**：图纸格内色号画在 `bead-board` 上，`ink`（#3D3226）在那上面几乎看不见。
   期望深色底上的文字与网格线各用哪个 token 有明确取值，且**不是**靠 `ink`（→ 任务 13、16）。
4. **像素字体没加载出来**：`font-display: block` 会先留白。若构建产物漏拷 woff2（或离线），整屏会一直
   空白而不是回退。期望构建后有一步「产物里确实有字体文件」的检查（→ 任务 5）。
5. **平板 768~900px 的三栏挤压**（§10.8）：左栏 236 + 右栏 262 + 间距已占 520px，中栏只剩约 248px。
   期望在这个区间有一个**真窗口看一眼**的验证步骤，而不是只看 1280（→ 任务 10）。

### Task 1: store 的裸涂色动作 `paintCells`

填充工具需要一个「把一批格子涂成某个色号」的动作，但现在 store 只有「涂成空格」的 `eraseCells`。
先把底层动作补上，**纯新增**，不碰任何既有行为。

**Files:**
- Modify: `src/stores/editor.ts`（`eraseCells` 约 363–372 行处）
- Test: `src/stores/__tests__/editor.test.ts`（`eraseCells` 那个 `describe` 之后追加）

**Interfaces:**
- Produces: `paintCells(indices: readonly number[], color: number): void` —— 把 `indices` 里
  **值不等于 `color`** 的格子写成 `color`，一条命令 = 一步撤销；`color` 可以是 `EMPTY`。
  空命令（全都已经是目标色）不提交、不置脏、不消耗撤销额度。
- Consumes: 既有 `requireLoadedPattern()`、`buildPaintCommand(cells, indices, value, label)`、
  `history.value.commit(...)`、`publishChange(...)`。
- 既有夹具：`seedEditor(cells?: readonly number[]): { editor, pattern, session }`。
