## 2. 最关键的一条根因

**覆盖层被挂在了吸顶 / 可滚容器内部，`z-index` 逃不出祖先的绘制顺序。**

`SheetViewer` / `ExportPanel` 自身写着 `fixed inset-0 z-30/40`，但它们的 DOM 祖先是 `SetupPage` 的
`preview-pane`（`position: sticky` + `overflow-y-auto`）与 `ResultPanel`。祖先建不出「让后代的 z-index
参与根层级比较」的层叠上下文，于是：生图页那条 `fixed inset-x-0 bottom-0 z-10` 的底栏画在覆盖层之上；
覆盖层没占满时触摸滑动仍落到下层页面的滚动容器上。

**「从图库打开没这问题」正是这条根因的反证**：图库路径把 `SheetViewer` 挂在页面顶层，没有这层祖先。
修法是挂载位置（`Teleport to="body"`），不是调大 z-index 数值；打印面板是查看层的子树，也必须自己
Teleport（`z-60`），否则仍被查看层那个层叠上下文 / 裁剪框住。

## 3. 本轮新增的裁定（R51–R57）与代价

- **R51** T3 只删 `ParamPanel` 的「生成图纸」按钮，保留旁边那段 `generateBlockedReason` 文字
  （它是「选区太小 / 存储不可用」唯一的原因来源）。代价：面板里留一段无按钮的说明文字。
- **R52** T1 的滚动锁用一个**计数式**共享 helper（`composables/useBodyScrollLock.ts`）。代价：多一个
  约 20 行的模块 + 一条单测。理由：施工图与打印面板会嵌套打开，各写各的 `overflow` 时先关的那层会把
  还开着的那层的锁一起还原掉。
- **R53** T5 的 `rerun` 顶栏按钮带可见「重做」二字 + 24px 图标（与结果页三颗动作同口径），
  `variant="secondary"`、`canRerun` 为假不渲染。代价：顶栏比纯图标版略宽。
- **R54** T6 的板底调亮与图纸外框**两处都做**：单靠外框在黑豆上仍偏弱，单靠亮底不改「图纸到哪结束」。
  代价：`bead-board` 与屏稿色不同（同一 token 的取值变更，已写入规格 §6.1 更正注记）。
- **R55** T4 复审：手机吸顶块由 `top-0` 改 `top-16`，让开顶栏的 64px，不再被顶栏压住。代价：`top-16`
  与顶栏 `h-16` 是两处硬编码的 64px、没有测试把二者耦合；768–1023px 宽时工具条折两行（见 §4）。
- **R56** T5 复审：结果页的「重做」改用新的 `rerun` 图形（原来复用 `undo`），与顶栏那颗同形。
  代价：无新权衡，纯图形替换。
- **R57** T6 复审：外框色改用 `bead-line`（`#C9B79A`），不用 `bead-hole`——后者对新板底只有 1.26:1
  对比度、与 `bead-grid` 只差 1.09:1，看上去就是又一条网格线。代价：`clampView` 让贴边那一轴的外框
  只剩 1px、外框内侧 1px 会盖住最外侧豆边（明示接受，不逐格让位）。

## 4. 验证读数与仍未验证的事

真窗口（msedge + Playwright CLI）**实际跑过**：

- `npm run test`：**89 文件 / 1639 用例全绿**。
- `npm run build`：`vue-tsc` 严格类型检查 + Vite 构建通过；`dist/assets/` 内含
  `fusion-pixel-12px-proportional-zh_hans-*.woff2`。
- 手机 390×844：①② 吸顶块停在顶栏下沿（`paneTop - headerBottom = 0`，参数区无 z）；③ 生成后跳独立
  结果页；④ 施工图 / 打印两层均 Teleport 到 body（`z-50`/`z-60`）、嵌套解锁正确、背景页不滚、图库路径
  不回归；⑤ 图标签名互不相同；⑥ 顶栏 [重做][保存]、工具条无 `rerun`；⑦ 画布采样到 2px 外框。

- **768–1023px**：工具条折两行的实际观感（机制必然，已接受为已知取舍）。
- **低亮度 / 强光下的对比度**：外框与调亮后的板底在暗屏上是否够清楚。
- **平板 SetupPage 三栏在 768–900px 的挤压**（规格 §10.8 要求「必须在这个区间看一眼」）。
- 平板 1「其余与手机相同」这条本身没有独立复验——它按定义由手机各条覆盖。
