## 4. 实现期被证伪、已写进规格「更正注记」的论断

1. §7.2「预算用字号上限 ⇒ 只会高估行数 ⇒ 不会溢出画布」**不成立**（预算列数按可用宽算、真实列数按网格宽算）：反例 30×92 + 221 色 ⇒ 旧实现 `canvasHeight 4340 > EXPORT_MAX_EDGE`。
2. §7.2 同源的打印页缺陷：纵向预算不含页面装饰带 ⇒ 70×58 + 58 板 + A4 第 2 页 + 40 色时用料条被静默裁到纸外（旧 3621 > 3508）。
3. §3.6.1「判据是 `history.state.back`，用例用 `createMemoryHistory`」：**内存历史不写 `back`**（只有 web 历史的 `buildState` 写），该函数的用例必须用 `createWebHistory`。
4. §6 的三行档位映射表与 `customMaxColors` 已被第 2 节的纯数字模型作废。
5. §6「自绘拇指 ≥28px」未实现（轨道 44px 即触控目标，拇指用浏览器原生尺寸）。
6. §3.4 的 `ResultPanel` props 清单漏了 `name`（实现为可选，默认「图纸」）。

## 5. 关键取舍（人类伙伴裁定）

- 打印页保持 **1:1（永不放大）**，只把标题 / 用料条 / 网格块三者左沿对齐（不加「铺满页面」选项）。
- 档位模型改纯数字时 **不做旧记录兼容**（A1）：库里读到 `"custom"` / `"all"` 一律按既有「用色档位非法」**响亮报错**；`32` 这类数字在新模型下**合法**。⇒ 旧图需删掉重建。
- 档位数字不再画在滑条上（B1，几何上不可能不重叠），改成滑轨刻度线 + 下方一行数字。
- 推翻 B4「不做连续多下载」：打印页一键保存会连发 N 次下载（交付面是 Android 壳）。

## 6. 延后项（**本阶段唯一真源**，下一轮从这里取）

### 6.1 判据缺口（最高优先，各几行）

1. `components/sheet/SheetViewer.vue:424`「计划到手后补量一次 `measure()`」**没有任何有判别力的判据**：删掉它，真机上查看层会退回「按钮点了没反应、不能拖」，而全套测试仍绿（现有用例都先派发 `resize`，绕过了这条主路径）。要一条**不派发任何 resize** 的建视图判据。
2. `services/__tests__/sheetExport.test.ts`（三处真调用）**丢弃了 `renderSheetBlob` 的返回值** ⇒ 「返回的 plan 就是那颗 blob 的几何」这条中心不变量全仓无断言（将来多调一次 `planSheet` 或用缓存 plan，比例尺会静默错）。

### 6.2 会真遇到的功能缺口

3. 查看层**三指后捏合进入死状态**（照搬 `PatternCanvas` 时漏了 restart 分支）；`@pointercancel` 也走轻点判定（`PatternCanvas` 是独立处理器）。

## 7. 流程教训（本轮实测，下一轮沿用）

1. **变异验证指令本身也要被怀疑**：本阶段三次出现「控制者指定的变异没有判别力」（`pageFilename` 就地改读实时选项、happy-dom 下同步 `dispatchEvent` + 微任务 DOM 补丁、`medianCut(N)` 在桶数 ≤ N 时提前返回）——实现者用有牙的等价变异替换后才真的判死。**给判据之前，先自己走一遍「改坏了这条会不会红」。**
2. **happy-dom 下的假绿三类**：`getBoundingClientRect()` 恒 0（所有缩放/布局断言必须先假造视口）、DOM 补丁在微任务里（读样式前要 `await nextTick()`）、`PointerEvent` 的 `buttons` 恒 0（拖动类判据要显式给 `buttons: 1`）。
3. **真机清单不许跳**：C8 把「查看层打开是整图可见」写进人工清单却没跑，缺陷活了两个阶段（`e7a75a7` 引入）直到人类伙伴上真机才暴露。**宣布完成前，人工清单逐条打勾。**
4. 每个任务的收尾都是「跑全套 + 两道闸门 + `vue-tsc`」，并且在**提交后的干净工作区**上复跑读数。
