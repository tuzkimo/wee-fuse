**收敛出的做法**（分派下一份计划时照做）：

1. **装配期必做接口成对机检**：凡「A 的输出喂给 B」，把两边名字逐个对契约求差集，**并对真实签名核一次**
   ——B4 靠它在派发前抓到两处真断裂（`drawLegend` 少传 `palette`、分享图格像素无来源）。
2. **判据的「判别力」不许由计划点名**：红数一律由实现者实跑回填、控制者与审查者各自独立复核；
   规格原文「写计划前实跑」在代码还不存在时不可执行，已改成「不许预估」。
3. **变异一次只放宽一条性质**：控制者的 P2 变异同时放宽「抛错」与「颜色」两半，那条红**掩盖**了
   「颜色半边零判别」的缺口（任务 5 的 F1 就是从这个缝里漏出来的）。
4. **变异脚本必须自证替换真的发生**（锚点命中数 = 1、文本确实变化、文件 SHA 变、numstat 非空），
   并且**0 红与全红一样先怀疑仪器**。
5. **两条实现数学上等价时，取值断言永远判不开 ⇒ 改成源码级结构约束 + 一条会把闸门打红的变异**
   （G-12 的正式条款，已写进规格 §4.4 第 3 条）。
6. **分派审查时在提示里给出审查包的行数与末三行**，让审查者自证读全（两位审查者都误判过「包被截断」，
   控制者两次用 `numstat` + 末行比对证伪——与其事后证伪，不如事前给判据）。
7. **「审查者的清单」也是未经核实的声明**：控制者照抄审查者给的「三处不兼容」，实现者用逐字段 `Omit`
   探针穷尽出**四处** ⇒ 引用别人的清单必须自己穷尽一次。
8. **工具的输出不能直接当证据**：`Get-Content .Count` 少算行数；PowerShell 默认大小写不敏感；
   无 BOM 的 `.ps1` 含中文被当 ANSI 读。
9. **测试替身要由「环境事实」逼出来**（真画布永不钳制、`toBlob` 给 size 0 永不 null、`getContext` 默认 null），
   否则造出的桩测不到真实失败形态。
10. **「既有断言一行未改」要作为审查项交独立重做**，并用**大小写敏感**的删除行过滤做定论性核对。
11. **账本要能被别人数出来**：`minor (deferred)` 必须落成**可数的行**（本轮为此自我纠正过一次，见 §3 第 15 条）。

## 4. 被推翻的结论

**R1（控制者写进契约 / 规格的接口断言）**：原来的结论——「`CanvasRenderingContext2D` 结构上满足
`RenderTarget2D`，无需转换」。**不成立**：对象类型赋值时属性协变，`fillStyle` / `strokeStyle`
（`string | CanvasGradient | CanvasPattern`）、`textAlign`（DOM 含 `"start" | "end"`）、`textBaseline`
（DOM 含 `"alphabetic" | "hanging" | "ideographic"`）四处都不成立。谁推翻：任务 3 审查者用编译器实测。
修法：`requireContext2D` 的返回类型改成 `RenderTarget2D` + 内部一次具名窄化；契约 §2 与规格 §3 都加更正注记。

**R2（控制者转述的清单）**：原来的结论——不兼容字段是「三处」。**不成立**：是**四处**（漏 `strokeStyle`）。
谁推翻：任务 3 实现者用逐字段 `Omit` 探针穷尽。修法：契约 / 规格 / 计划三处同步。

**R3（控制者的裁定）**：原来的结论——「内部一次具名窄化」可以照字面单独实施。**不成立**：
`assertCanvasPainted` 要调 `getImageData`，而它不在 `RenderTarget2D` 里（before 原文含 TS2339）。
谁推翻：任务 3 实现者；复审者用独立探针复现。修法：加一个**不导出**的 `requireRawContext2D`，
两条路径共用同一处 null 守卫，导出面仍是契约的 6 个。

**R4（契约自造的字段）**：原来的结论——`LegendPlan.footerY` 是一个有用的页脚起点。**不成立**：
它与 `totalY` **代数恒等**，且规格从未定义这组坐标（是控制者在契约里自造的），任务 2 全程只用 `totalY`
⇒ 零消费者。谁推翻：任务 1 审查者（F2）。修法：删字段；规格 §5.4 补写这组坐标的语义
（`totalY` = 页脚三行起点，`+2 / +16 / +30` ⇒ 合计 44 = `SHEET_FOOTER_H` 正好放下）。

**R5（计划强制的断言）**：原来的结论——任务 1 的 `vLines` 断言能判别「分片只挪原点」。**不成立**：
全部 `vLines` 读取都落在原点 0 的片上（去掉 `− originCol` ⇒ 30 passed，**0 红**）。谁推翻：任务 1 审查者（F1）；

写进规格 §13.2-2 / §13.3。

**R6（计划强制的用例）**：原来的结论——`share.test.ts:76` 的「四角」覆盖了空格不画的路径。**不成立**：
(5,5) 是**实心格 3**（同文件另一处反而断言它被填成浅灰），`EMPTY` 分支**一次都没执行**。谁推翻：任务 2 审查者（F1）。
