## 2. 这一轮的主线：**计划的「代码块」与「判别力构造」都不可信**（第七次确认）

计划 A 的教训是「断言存在 ≠ 断言有效」，B1 是「我写进计划的代码块不可信」，B2 把后者推进成
「**我给出的『这条变异应当红 N 条』这类判别力构造本身也不可信**」。**B3 全程带着这条纪律，
结果是：八个任务没有一个的简报代码块可以直接照抄，也没有一个任务的变异期望红数全部正确。**

## 4. 被推翻的结论

1. **「`visibleCellRange` 的 `null` 是防御性分支、不可达」→ 不成立**（任务 1 审查者）。饱和夹取让
   `x1 < x0` 不可达，但「图纸整块在视口外」是**无交集**、与「区间反向」不是同一件事；规格 §4.5 明文要求
   返回 `null`。修法：交集判定放在饱和夹取**之前**（右端仍取 `ceil`，因为 `ceil(hi)-1` 会丢掉「起始边恰好
   压在视口边缘」的那一格，而规格要求含它）。
2. **「`cellsAlongLine` 的端点规范化有判别力」→ 不成立**（审查者用脚本复算）。简报那条夹具
   （`(2,7)→(15,3)` 与反序）在**朴素 Bresenham** 下本来就互反，所以那条用例照抄也绿；真正不对称的是
   `(0,0)↔(2,1)`。补了一条判别用例后成立。
3. **「P11 的零守卫」= 假绿**（任务 6 复审）。第一轮探针报「`toggle-labels` 的 `aria-pressed` 绑成
   `showGrid` 时 13 条全绿」，实际既有两条用例（`showLabels:false` + 默认 `showGrid:true`，两值相反）
   **本来就会红**；那个 0 红是**探针/测量没生效**。⇒ **「0 红 ≠ 无守卫」**，探针表的 0 红必须区分
   「变异没生效」与「真的没人守」。
4. **「审查包不是逐字节可信的 git 输出」→ 不成立**（控制者核）。见 §3 第 6 条。
5. **实现者的三处过度声称**被逐条纠正（记账）：`NEW_THUMBNAIL.startsWith("data:image/")` 是**夹具自检**
   （happy-dom 对任何画布都返回 `"data:image/png;base64,"`，对 `project.ts` 的任何改动都不会红）；
   `markRaw` 那条端到端断言恒真；`@407` 那半句「恰好有判别力」不成立。
6. **「`markDirty` 缺口是必须修的缺陷」→ 不成立**（审查者独立判定）：③④⑥ 的 `dirty===true` 被 `adopt`
   的副作用满足、抓不住 no-op，但能抓「把方向改错」，而 `markDirty` 的必需语义已被用例 ① 独立钉死
   （空实现红 1、toggle 红 7）。⇒ 归次要。
7. **「变异 R6 是漏守卫」→ 不成立**（实现者自陈 + 复审确认）：越界守卫里的 `EMPTY` 检查因前面那句
   早退而不可达；若为让它生效而删早退，`colors[65535]` 变 `undefined` ⇒ 抛错 ⇒ EMPTY 用例立刻红，
   说明**早退本身有守卫**。⇒ 不为不可达分支硬凑断言。
8. **任务 8 的「全绿 = 端到端存在」被自己证伪**：删掉端到端 ① 后全量 976 用例 **0 失败**（A9 审计）。
   ⇒ 存在性交给标题 `grep`，不交给「全绿」。
9. **计划文档 `:7805/:7806` 的示例数字全部过时**（最终复审者）：写着「+8 文件」「`EditorPage.test.ts`
   5 → 30 条」，实际是 +7 文件、7 → 41 条；锚点「47 文件 / 755 用例」也已与当前 README 对不上。

### 10.1 C-1：**切工程时不载入新图纸**（B3 唯一的用户可见功能 bug）

- **现象**：有未保存改动时从 `/edit/a` 切到 `/edit/b`，确认后 **URL 是 b、画布还是 a**——此后每一笔都改在 a 上，
  且没有任何迹象提示用户。可达路径：**平板返回键在两个 `/edit/:id` 之间来回切换**（那是同记录只变参数）。
- **机制**：同记录只变参数时 `onBeforeRouteLeave` **不触发** ⇒ 是 `watch(() => route.params.id)` 先醒、
  只拉起确认条并 `return`，**而那次导航其实已经提交**（`currentRoute` 已是 `/edit/b`）⇒ 用户确认后
  `replayPending()` 的 `router.push` 目标与当前地址**逐字相同** ⇒ vue-router 视为重复导航 ⇒ `route.params.id`
  不再变化 ⇒ **`watch` 不醒 ⇒ `activate("b")` 永不执行**。真实路由器读数：`loadedAfterSaveAndLeave: "a"` /
  `pathAfterSaveAndLeave: "/edit/b"`。
- **注释就是 bug 的源头**：`EditorPage.vue` 原 `:283-284` 写着「真实路由器随后把 `route.params.id` 变成它，
  `watch` 于是再跑一次并真正载入」——而这个假设恰好反了。
- **测试为什么没抓到**：那条用例在确认前**手动把 `route.params.id` 退回空值再设成 `b`**，注释还写明了理由。
  **用例替生产代码补了 bug 所在的那一步。** ⇒ 这是「断言存在 ≠ 断言有效」的第三种变体，已写进 §6。
- **修复**：`replayPending()` 自己比对并 `activate(nextId)`（`loadedId` 在 `activate` 入口同步写 ⇒ 只载入一次）；
  用例按真实顺序重写（**替换语义**：原有 6 条断言一条未删，新增 4 条 + 1 条「`load` 恰好一次」契约断言）。
  判别力证据：回退那两行 → **恰好 1 红**（失败点标题仍是「小猫 `2 × 1`」而 URL 已是 b）。
