# 去背景（事前 + 事后）设计

> 2026-10-11。人类伙伴与助手头脑风暴的产物。**本文是真源**：实现计划、构建记录里关于去背景的
> 语义一律引本文，不要各写一份。

## 1. 意图与 why

拼豆图纸里「背景」通常不拼。当前两张来源都做不到这件事：

- `buildPattern` 会把裁剪区里**每一格**都映射成某个色卡色号——背景照样占豆子、照样占**用色名额**
  （16 色里浅灰渐变背景能吃掉 3–4 色，全部是从主体身上抢的）。
- 编辑页只有橡皮，一格一格擦不现实；框选擦是方的，抠不出主体轮廓。

人类伙伴的图基本是**纯色或渐变背景**，很少有杂物背景。所以不需要抠图模型：一个「从已知背景点
往里长、颜色差在容差内就吃掉」的四连通泛洪就够，纯前端、零依赖、毫秒级。

人类伙伴对**失败方向有明确偏好**：更怕「吃过头」（主体被啃掉，只能重做），不怕「吃不够」
（残留一圈脏边，手动补两下）。本文所有默认值都服从这条：**宁少勿多**。

## 2. 目标

1. 参数页一个「去除背景」开关：勾上后，生成时背景格直接变成空格（不拼豆），且**用色名额让给主体**。
2. 编辑页一个「去背景」工具：点一下背景，与该点连通的背景整片变空格，**一步可撤销**。
3. 两条路共用同一个泛洪算法，不写两份「哪些格子是背景」的判定。

## 3. 非目标

- 不引入 AI / 抠图模型 / 任何新依赖。
- 不做容差滑条（见 §7.2）。
- 不做框选去背景、不做「按色号全图删除同类色」（渐变背景会漏，且会误伤主体同色区域）。
- 不做边缘羽化 / 半透明处理；抗锯齿过渡带允许残留。
- 不改 `Pattern` / `EMPTY` / 导出 / 施工图 —— `EMPTY` 一路已经通到底。

## 4. 已定（人类伙伴的决定）

| 决定 | 内容 |
|---|---|
| 产物形态 | 去掉的是「格子」，变成 `EMPTY`（不拼豆），不是涂白、不是涂某个色号 |
| 两条路都做 | 事前（参数页开关，量化前排除）+ 事后（编辑页工具，手动补） |
| 事前失败怎么办 | 不做修补机制：效果不好就取消勾选、重生成，再用手动工具收尾 |
| 事后交互 | **点一下**背景（不是划、不是框） |
| 偏爱方向 | 宁少勿多，吃过头是更坏的失败 |

## 5. 算法（唯一一份）

新增 `src/core/pattern/background.ts`：

```ts
/** 从若干种子格出发，四连通吃掉颜色相近的格子，返回被吃掉的格子下标。 */
export function floodBackground(
  width: number,
  height: number,
  labs: Float32Array,     // 长度 w*h*3，逐格 Lab
  eatable: Uint8Array,    // 长度 w*h，1 = 可吃（空格/透明格为 0）
  seeds: readonly number[], // 起始下标
  tolerance: number,      // ΔE76 阈值，有限且 ≥ 0
): number[];
```

规则：

- **四连通**（上下左右）。八连通会沿对角从背景漏进主体，与 §1 的偏好冲突。
- **每个种子以自己的颜色为基准**：BFS 入队时把该格所属的种子 Lab 带下去，判定用
  `ΔE76(格 Lab, 所属种子 Lab) ≤ tolerance`。于是渐变背景（各角颜色不同）能各自成片被吃，
  而不会因为「相邻色差小」一路爬进主体。
- 种子格自身必须 `eatable = 1`；不可吃的种子直接跳过。
- 度量用 `colorDistance(..., "de76")`（与逐格映射同口径：性能优先）。
- 入口校验：`width/height` 是 ≥ 0 的整数（0 表示空图，直接返回空数组，与 `patternStats`
  既有契约一致）、两个数组长度自洽、`tolerance` 有限且 ≥ 0、种子越界或非整数一律抛错
  （`AGENTS.md`「入口校验」：响亮失败在任何写操作之前）。

容差常量 `BACKGROUND_TOLERANCE = 10`（ΔE76 量纲 0–100），模块内常量、**不进 UI**。

## 6. 两条路的接线

### 6.1 事前（参数页开关 → 量化前排除）

- `SampledGrid.filled` 已经就是「这格拼不拼豆」，`buildPattern` 已经**只处理 `filled !== 0` 的格**
  （直方图、聚类、逐格映射都是）。所以事前只需在量化前把背景格置 0，**不用改 `buildPattern`**。
- 接入点：`services/pipeline.ts` 在 `rotateGrid` 之后、`buildPattern` 之前。
  `sampled` / `rotated` 都是该函数局部的，就地改 `filled` 安全。
- **事前不猜背景色，用四角当种子**：取裁剪区旋转后的四个角格（各自 `filled !== 0` 才算）当种子，
  每个角以自己的颜色为基准泛洪。理由：
  - 零新交互（勾上就自动）；
  - 主体贴四条边的概率不低，但**同时压住四个角**的图几乎不存在——所以比「整条边当种子」安全得多；
  - 纯色背景四角同色 ⇒ 整片背景被吃；渐变背景四角异色 ⇒ 各自吃一片，接缝残留 ⇒ 正好是宁少勿多。
  - **已知风险**：主体本身压在某个角上（例如人像贴角）⇒ 那个角的那片会被吃过头。代价可控：
    取消勾选、重生成即可，且人类伙伴已接受这条路线的失败后果。
- `GenerateRequest` 加 `removeBackground?: boolean`；`deps.palette` 已有，labs 用 `rgbToLab` 逐格算。
  开关不为 `true` 时这一步整个不执行（行为与今天逐位一致）。
  **这里故意用可选字段**（与本项目「缺字段就响亮失败」的惯例相反），理由是它的缺省语义**就是**
  老行为、不可能静默产错，而 `pipeline.test.ts` 有 22 处内联请求字面量，必填会换来 22 行无信息
  的改动。落盘参数那一侧则是另一回事（见 §6.2）。

### 6.2 落盘参数

- `ProjectParams` 加 `removeBackground: boolean`，`core/project/file.ts` 的读写两处同步。
- **旧记录缺这个字段时按 `false` 读，不做迁移、不报错**。这跟 C7/C8「旧值一律不做兼容」的先例
  不冲突：那不是「旧值换了格式」，而是新增一个可选字段，且缺省语义**就是老行为**——老工程打开后
  的表现与今天完全一致。这也是唯一安全的选择：按 `validateProjectDocument` 的严格口径把它当必填，
  会让**库里所有已有工程全部打不开**。
- 需要一并接线的字段副本（B2 起参数在草稿里有多处出口）：`stores/draft.ts` 的 ref + 播种 + 复位 +
  `toGenerateRequest` 路径、`views/SetupPage.vue`、`components/param/ParamPanel.vue`（勾选框）、
  `services/rerunDraft.ts`（改参数重新生成要把开关带上）、`core/project/file.ts` 双向映射。
  **B2 的教训**：参数副本漏传一处是静默的（`rerunDraft` 当年就漏过一个），所以实现时以
  `longSide` 为清单逐个 grep，漏一处即测试失败。

### 6.3 事后（编辑页工具）

- `EditorTool` 加 `"background"`（第 4 个工具：`brush` / `select` / `pick` / `background`）。
  注意**橡皮不是工具**，它是「当前色 = `EMPTY`」——去背景是工具。
- `PatternToolbar` 加第 4 个按钮（文案/图标按现有风格，放末位）。
- `PatternCanvas`：按下时起 `"background"` 手势（与 `pick` 同为「单点」形态），抬手
  `emit("background", cell)`；既有叠加层逻辑不改。
- `EditorPage.onBackground(cell)`：用页面已有的 `palette`（`createPaletteRuntime(palette).labs`）
  填 labs，`eatable = cells[i] !== EMPTY ? 1 : 0`，种子 = 该格，调 `floodBackground`，把得到的
  下标交给 store。
- `stores/editor.ts` 新增一个动作（约 10 行）：`eraseCells(indices: readonly number[])`
  → `buildPaintCommand(cells, indices, EMPTY, "去背景")` → `history.commit` → `publishChange`。
  **不新写任何判定/入账逻辑**：
  - `buildPaintCommand` 本来就跳过「已经是目标值」的格 ⇒ 点空格得到空命令 ⇒ 不消耗撤销额度、不标脏；
  - 一次点击 = 一条命令 ⇒ 撤销一次回退整片，走的还是既有 `EditHistory`。

## 7. 边界与失败模式

1. **点空格 / 点主体**：点空格无操作；点主体则吃掉该主体中与种子色差 ≤ 容差的一整片 → 撤销一步可退。
2. **整图被吃空**：允许。事前：`buildPattern` 的 `filledCount === 0` 分支已返回全 `EMPTY` 图纸；
   事后：`patternStats` 对全空格图正常（`total = 0`）。不做「至少留一格」的守卫——那是替用户做决定，
   而撤销 / 取消勾选是明确出路。
3. **0×0 空图**：返回空数组，不抛错（`patternStats` 的既有契约如此）。
4. **容差、尺寸、数组长度非法**：入口抛错。
5. **渐变跨度超过容差**：残留，靠事后工具在残留处**再点一下**（新种子、新基准色）继续吃。
   这就是手动微调机制，不需要滑条。
6. **`rotateGrid` 在 `rotation === 0` 时返回入参本身**：事前就地改 `filled` 会同时改到 `sampled`，
   两者都是 pipeline 局部变量、改后无人再读，安全；实现时保留一句注释说明。

## 8. 测试要求

core 纯函数（`floodBackground`）：

- 纯色背景（四边/四角同色）整片被吃；
- 渐变背景：跨度在容差内的片被吃，超出容差的那头残留（宁少勿多）；
- 与种子色差大于容差的块挡住泛洪，**不越界**；
- 图上另有一块「与背景同色但不连通」的区域**不被吃**；
- 八连通可达、四连通不可达的对角情形不被吃；
- 种子不可吃（空格）→ 不产出；越界/非整数种子 → 抛错；
- 容差为非有限值或负数 → 抛错；0×0 → 空数组。

集成 / store：

- pipeline：勾选后背景格全为 `EMPTY`，且实际用色数 ≤ 未勾选时的用色数（背景不再占名额）；
- 落盘往返：新记录写入并读回 `removeBackground`；**没有该字段的旧记录能打开且等价于 `false`**；
- 编辑页动作：一次 `eraseCells` 一次撤销即全部还原；对已经是空格的格子调用不产生撤销记录、不标脏。

## 9. 留给实现者的裁定

- 容差取 `10`、度量取 ΔE76、四连通：已定（§5）。
- 勾选框文案、工具按钮图标、工具在工具栏里的次序：按现有 UI 风格自取。
- BFS 用数组队列即可，**不要**引入优先队列或递归（116² 上限下没有意义）。
- 事前复用的「四角」取**旋转后网格**的四个角格：`(0,0)` / `(w-1,0)` / `(0,h-1)` / `(w-1,h-1)`
  （格坐标，不是像素角），避免在 core 里再引入一份坐标数学。
