# 编辑页填充与工具改造设计

> 2026-10-13。人类伙伴与助手头脑风暴的产物。**本文是真源**：实现计划、构建记录里关于本功能的
> 语义一律引本文，不要各写一份。
>
> 本批只覆盖**编辑页**（1–4 条）。生图页 / 结果页的三条（预览区固定不滚动、预览改成施工图中间
> 那块、调参实时预览）是独立的一批，**另立规格**，不在本文范围内。

## 1. 意图与 why

人类伙伴的原话场景：

> 我用画笔在空白区域画了个图案，然后想在中间填色，却发现空白区域无法填色；如果手工涂色，
> 一个不小心就把刚画好的边界涂了。

也就是说：**空格是画布，不是空洞**。现在它被当成墙（§4.1），于是「先画轮廓、再灌内部」这条最
基本的画图路子走不通，只能一格一格手涂——而手涂必然压到刚画好的轮廓上。这是本批里人类伙伴
点名的**最大痛点**。

同一次头脑风暴还带出另外三条编辑页的实机问题：橡皮的入口位置不合手、双指拖动在真机上难用、
去了背景的黑线图与深色板底糊在一起。四条同一个页面、同一批实机反馈，合成一批。

## 2. 目标

1. **空格可填**：手里拿颜色、点在一个空格上，把**与它连通的整片空格**一次涂成该颜色
   （四连通，碰见任何有颜色的格即止）。一次点击 = 一条命令 = 一步撤销。
2. **橡皮的入口搬进选色区**：删掉工具栏那颗独立的「橡皮」按钮；橡皮作为选择器里的一个条目
   （它在 `recolor` 用途下已经存在），在画笔用途下也提供。
3. **新增「拖动」工具**：单指拖动平移视图；**进入编辑页默认就是它**。双指缩放 / 平移保持现状。
4. **图纸矩形内铺浅色纸底**：板底只在图纸外露出。于是「去了背景的黑线图」看得见，空白区也
   一眼就是「可以填的地方」——它和第 1 条是同一件事的两面。

## 3. 非目标

- **不做**填充的「相似颜色容差」滑条（Paint 里的那颗勾选），也不做「填到全图所有空格」。
- **不做**轮廓闭合检测 / 缺口自动补：手绘轮廓有缺口时漏到外面那整片空白，这是标准油漆桶的
  行为，撤销一步接得住（§5.1）。
- **不做**拖动工具的惯性滚动、双击缩放、缩放锚点跟随。
- **不改**落盘语义：`Pattern` / `EMPTY` / 工程文件格式、导出、施工图、任何生成参数都不动。
- **不动**生图页与结果页（§1 引的那三条另立规格）。
- **不给**拖动工具加任何重绘以外的反馈（不做光标变化、不做边界回弹）。

## 4. 先例与推翻（必读）

### 4.1 「空格是实心墙」是本批要推翻的核心约定

`core/pattern/background.ts` 的 `floodBackground` 契约里逐字写着：

> 不可吃的格（空格）既不被吃、也不被穿越，是实心的墙；

`patternBackgroundIndices` 据此让空格永远不可吃（把 `EMPTY` 格一律置成 `eatable[i] = 0`），
并且在种子本身是空格时直接 `return []`（推导：`floodBackground` 对 `eatable[seed] !== 1` 的
种子直接跳过，所以那条早退只是把结果写死）。

**这条约定对「事后去背景」是对的**（空格是抠出来的洞，泛洪不该穿过去继续吃），**对「填色」是
错的**（空格是待涂的位置）。本批把它改成**按种子的状态分岔**（§6.1）：种子是空格 ⇒ 可吃的是
连通的空格；种子有颜色 ⇒ 维持原口径，一个字节都不变。

### 4.2 两条既有断言与本批直接冲突（已获人类伙伴批准修改）

按 `AGENTS.md` 的例外条款——「已有断言与新的规格要求直接冲突时，经人工确认可修改，禁止为让
代码变绿而放宽、删除或改弱断言」——本批涉及两条，人类伙伴在 2026-10-13 的头脑风暴中明确要了
这个功能，即人工确认：

| `components/editor/__tests__/PalettePicker.test.ts:157` | `mode: "brush"` 时**没有** `picker-eraser` | 反转为「有」 |
| `components/editor/__tests__/PalettePanel.test.ts:398` | 画笔模式下 `picker-eraser` 不存在 | 反转为「存在」 |

另有两具**随功能一起消失**的主体，它们的用例是被连带删除而不是被改弱：`PatternToolbar.test.ts`
里关于 `data-testid="eraser"` 的四条（`:46` 的 aria-label 表、`:252` 的尺寸表、`:319–325` 的
行为用例），以及 `EditorPage.test.ts` 里走 `@eraser` 的那条路径。

### 4.3 规格 §6.1「看图一律深色衬底」的更正

像素风 UI 规格（`docs/superpowers/specs/2026-10-12-pixel-ui-design.md`）§6.1 定了「看图一律
深色衬底」，`PatternCanvas.vue` 的 `draw()` 里有一条注释逐字执行它：

> 空格不铺底：透明格透出容器那层深色拼豆板

本批给这句话加一个前提：**深色板底照样是画布外那一圈的底**，只有图纸矩形内改由浅色纸底铺底。
改的是「图纸内部」，不是「看图底」，§6.1 对画布外那一圈仍然逐字成立。

## 5. 交互与状态（已定）

### 5.1 填充

手里拿**颜色**、点在格子上：

- 该格**有颜色** ⇒ 现状逐字不变：泛洪同色连通区（容差 0），整片改成手里那个色。这是「区域换色」。
- 该格是**空格** ⇒ 泛洪**连通的空格**，整片改成手里那个色。**这条是新增的**。

手里拿**橡皮**（`EMPTY`）、点在格子上：

- 该格**有颜色** ⇒ 现状逐字不变：容差 10 的「去背景」，把连通的近色区擦成空格。
- 该格是**空格** ⇒ 无操作。实现上不额外写分支：泛洪返回 `[seedIndex]`，`paintCells` 涂 `EMPTY`
  是恒等操作。

两条口径：

- **四连通**，与现状一致。手绘的斜线阶梯在这一口径下是封闭的（对角相邻不算连通），所以
  「用画笔画个圈、点里面」不会漏到外面——人类伙伴的原话场景正好走这条。
- 轮廓有 1 格以上缺口时会漏出去。**这是标准油漆桶的行为，本批不改**（§3），一次撤销全还原。

一次点击 = 一条 `buildPaintCommand` = 一步撤销，这条现状已经满足，本批不动。

### 5.2 橡皮搬进选色区

- 选择器（`PalettePicker`）的橡皮条目在两种用途下**都渲染**（`data-testid="picker-eraser"` 不变）。
- 该组件里 `mode` prop 的**唯一**消费者就是那个 `v-if`（全文件搜 `props.mode` 只有一处）。
  两模式行为一致之后它是死参数 ⇒ **连同 prop 一起删除**，不留「保留着以后用」的余地。
  - `PalettePanel` 的 `pickMode` 还要继续决定**行为**（`onPick` 里分岔「批量换色」与「改画笔
    色」），所以这个 ref 保留，只是不再往选择器里传。
- 工具栏的 `eraser` 按钮、它的 `eraserActive` prop、`eraser` emit、`EditorPage.onEraser` 与
  模板上的 `@eraser` 一并删除。
- **`EditorPage.onEraser` 原来还顺手 `setTool("brush")`，这个行为一起消失**——不切画笔正是想要的：
  「橡皮 + 填充」= 大片擦除，而它现在就是 §5.1 里那条容差 10 的去背景。若切回画笔，用户就没有
  办法用填充橡皮了。
- 「当前色槽显示橡皮」的现状不变（`palette-current` 的 `v-else` 分支），只把它的注释里
  「独立的橡皮按钮在工具栏上」改成新的事实。

### 5.3 拖动工具

- `EditorTool` 变成 `"brush" | "fill" | "pan"`；`DEFAULT_TOOL` 改成 `"pan"`。
  - `DEFAULT_TOOL` 有三个消费者，全部自动跟着改，不用逐处写：`tool` 的初值、`loadPattern`、
    重置路径（`stores/editor.ts:50, 128, 195, 221`）。
  - `setTool` 的**运行时**枚举校验必须加上 `"pan"`（`stores/editor.ts:255`）。不加的话默认值自己
    都过不了那道闸门，而它是 TS 类型挡不住的那一层（注释里写了理由：`JSON.parse` + 强转）。
- 工具条按现有 `TOOLS` 表加一行 `{ tool: "pan", label: "拖动" }`；`PixelIcon` 的 `ICON_NAMES` /
  `ICONS` 加一枚 `pan`（12×12 栅格、只取 1 或 2 的线宽，与本文件其它图标同口径）。
- 手势：`PatternCanvas` 的 `ToolGesture` 加第三种 `{ kind: "pan"; pointerId: number; start: Point;
  startView: ViewTransform }`。
  - **按下**：沿用现有的「落在图纸外什么都不做」守卫（人类伙伴裁决 3）。这条守卫不会让用户
    「拖不动」：`clampView` 不许视图露出空白 ⇒ 视图缩小时图纸铺不满的那一轴上本来也无处可移，
    缩放到铺满时整个视口都在图纸内。
  - **移动**：按 `start` → 当前的位移 + `startView` 套 `panCellView`，走 `emit("update:view", …)`
    ——与双指那条同一出口。**不自己 `draw`**：视图生效一律走父级回灌 `props.view`，组件不假设
    自己算出的视图被接受了（既有注释已钉住这条）。
  - **抬手**：不发任何命令（`finishToolGesture` 对 `pan` 直接返回）。
  - **第二根手指落下**：现有分支已经 `toolGesture = null` 并转入 `startViewGesture()` ⇒ 拖到一半
    加第二指无缝变成捏合，这条不用新写。
- 平移**不进 `lastDirty`、不进历史**：它是视图变化，不是图纸改动。

**这条默认值的代价，先说清楚**：进编辑页之后**第一下拖动不会涂色**（它是平移），要涂色得先
点一次「画笔」。人类伙伴在 2026-10-13 明确要了「进入编辑页默认就是拖动」（原话：双指拖动很难
用），但这条与 §1 的主场景（「先画轮廓、再灌内部」）是紧挨着的两件事。真机上觉得别扭时，改
`DEFAULT_TOOL` 这一个字符串就能回去，不需要动其它任何东西——所以现在按人类伙伴说的定。

**连带一处夹具**：`views/__tests__/EditorPage.test.ts` 的 `dragPaint` 夹具（`:308` 一带）现在
**不先选工具**，它靠的就是「默认 = 画笔」。约 25 条用例走这个夹具（`:609`–`:1662` 一带，另
`EditorPageRouterLink.test.ts:177`），它们考的是 `revision` / 脏标记 / 撤销 / 保存那整条主链路，
不是考默认值 ⇒ 修法是**在夹具里先点一次 `tool-brush`**，一处改动全部复绿。默认值本身由
`stores/__tests__/editor.test.ts` 单独钉住，两者不要混。

  `fillRect(view.offsetX, view.offsetY, width*cellPx, height*cellPx)`。
- 新常量 `PAPER_ON_DARK` 落在 `components/ui/beadColors.ts`，值借设计系统里「纸」那一档

  `FRAME_ON_DARK` 借 `--color-bead-line` 完全同一写法（`_ON_DARK` 这个后缀的意思是「画在深色
  板底这张画布上」，不是「颜色是深的」）。
- 已知的连带效果（不改代码，只需知道）：空格的透明像素现在透出纸底而不是板底。
- **外框 `FRAME_ON_DARK`（`#C9B79A`）保留**：它紧贴纸底的那一侧对比度很低（约 1.1:1），可能
  看起来像消失了；但外半边仍贴着深板底，且删掉它要动用例、动 §6.1 的一条更正注记。先留着，
  进 §8 真机清单——若看起来就是纸边上一道脏痕，再单独删。

#### 更正注记（2026-10-13，真机反馈后）

人类伙伴在平板上看过之后原话：「那层浅纸底因为是纯色的，容易混淆，我觉得像施工图那样棋盘底纹
会好一些」，并且选定「照抄施工图的斜线」（而不是棋盘）。也就是说：**纯色纸底不够，空格还得有
底纹**。

于是本节的「空格的透明像素透出纸底」改成：**空格 = 纸底 + 一条斜线**。

- 斜线的色与方向**取自施工图**：`core/render/sheet.ts` 的 `EMPTY_STROKE`（`#e2e8f0`，
  左上 → 右下）。它从 `const` 改成了 `export const`，编辑器直接复用它——「空格长什么样」
  在施工图上早就定下了，本批不该另立一套。
- 只给**可见的**空格画（`drawEmptyHatch` 扫 `visibleCellRange`，与网格线同一道判空守卫）：
  116×116 的空图有上万条线，一轮 `draw()` 都扫整张图纸会把平移变成卡顿。
- 先收集坐标、再共用一次 `beginPath` / `stroke`（与 `sheet.ts` 的 `paintCells` 同构）。
- 层序：纸底 → 色块层 → **空格斜线** → 网格线 → 外框 → 色号 → 手势预览 → 选中高亮。
  斜线在网格线之前，与施工图一致；斜线在色块层之后（不是之前）——它只落在空格上，
  位置对画面无可观察差异，但这个位置保留了「`range === null` 时整块跳过叠加层」那条既有不变量
  （见 `PatternCanvas.test.ts` 的「可见格判空」用例）。
- 线宽 = 一个设备像素（与 `drawGrid` 同口径）。

**仍然未动**：纸底颜色（`PAPER_ON_DARK`）与外框（`FRAME_ON_DARK`）。真机上「斜线够不够」
比「底色深一档」更早被验证；底色要不要跟着改，等下一次真机反馈。

## 6. 实现要点

### 6.1 `patternBackgroundIndices` 改名并改口径

函数现在要回答的不再是「哪里是背景」，而是「与这一格同质的连通区在哪」⇒ 改名
**`patternRegionIndices`**，同步改 `EditorPage.onFill` 与 `core/pattern/__tests__/background.test.ts`。
（我的裁决：不改名则名字和注释都在说谎，而这个名字的读者只有两处。）

`eatable` 的建法按**种子**分岔：

- 种子是 `EMPTY` ⇒ `eatable[i] = cells[i] === EMPTY ? 1 : 0`；
- 种子不是 `EMPTY` ⇒ 维持现状逐字不变（`EMPTY` 与色卡外下标都不可吃）。

`cellLabs` 的建法**不变**（空格留 `0,0,0`）：种子是空格时基准就是 `0,0,0`，其它空格也是
`0,0,0`，ΔE76 = 0 ≤ 任何合法容差 ⇒ 不需要为空格造颜色，也不需要为这条路径另传一套容差。

`if (cells[seedIndex] === EMPTY) return [];` 这一行**删除**。

其余一律不动：校验顺序、越界 / 非整数返回 `[]` 的口径、`floodBackground` 内部的种子校验。

### 6.2 不动的东西（写出来免得顺手改坏）

- `EditorPage.onFill` 的容差选择（`color === EMPTY ? BACKGROUND_TOLERANCE : 0`）**不动**：种子是
  空格时容差用不上，种子有颜色时两条语义都与现状逐字相同。
- `floodBackground` 本体**不动**：它是共用的，事前路径 `maskBackground` 还在用，而
  `maskBackground` 的「空格不可吃」正是它需要的。
- `core/pattern/edit.ts` 的 `buildPaintCommand`、`stores/editor.ts` 的 `paintCells` **不动**。
